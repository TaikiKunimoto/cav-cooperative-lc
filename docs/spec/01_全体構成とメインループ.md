# 01 全体構成とメインループ

## 実行（`__main__.py`）

`TraCI/` を作業ディレクトリにして `uv run python -m v2 <seed> <Q> <f> [オプション]` で 1 回の実行をする（環境の `sumocfg` のパスは `TraCI/` からの相対）。

| 引数 | 意味 |
|---|---|
| `seed` | 乱数の種。`random.seed(seed)` に文字列のまま渡す |
| `Q` | 総流入量 [veh/h] |
| `f` | 必須 LC 車の比率（0..1） |
| `--env NAME` | 評価環境（`ENVIRONMENTS` のキー。既定 `diverge`） |
| `--obstacle L,P,T` | 突発障害物（レーン・位置・時刻。`Obstacle.from_spec`。02） |
| `--policy P` | 調停ポリシー。`edf`（既定）・`none`・`off`・`off-late`（下記） |
| `--activation-margin M` | 要求を出し始める位置（締切の何 m 手前か）。正の値だけ受け付ける。省略すると環境の既定（`Environment.default_activation_margin`） |
| `--set NAME=VALUE[,...]` | `constants.py` の定数の上書き（下記） |
| `--nogui` | `sumo-gui` でなく `sumo` で回す |

- 位置引数が 3 つ未満のとき，Q・f が数値でないとき，`--env` が未知のとき，`--activation-margin` が 0 以下のときは，理由を表示して終了する。
- 流入の時間 T は `__main__.py` の `SIMULATION_TIME`（600 s）で決まる。`constants.py` には無いので `--set` では変えられない。
- `--set` は `_apply_constant_overrides` が `sys.argv` を直接読み，ほかの v2 モジュールを import する前に `v2.constants` の属性を書き換える（各モジュールが `from v2.constants import X` で import 時に値を束縛するため）。名前は `constants.py` にある大文字の名前（`_` で始まらない）に限り，値は float にする。未知の名前なら終了する。`--set` は何回でも，`--set=...` の形でも書ける。ほかの定数から導出される値（`TC = TIME_STEP` など）は計算し直さないので，変えるときは直接指定する。
- 出力名は `v2_<env>_inflow<Q>_mlc<f>_seed<seed>`（`edf` 以外は先頭が `v2-<policy>`）。`--activation-margin` に `ACTIVATION_MARGIN`（400 m）と違う値を指定したときは `_am<M>` を，`--set` があれば `_set-<NAME><VALUE>-...` を足す。出力先と最終的なファイル名は 06。
- SUMO は `traci.start([binary, "-c", sumocfg, "--time-to-teleport", "-1"])` で起動し，`V2Simulation(...).run(stats)` を呼ぶ。

車は生成時（`V2CAV.model_post_init`）に，ポリシーによらず `setMinGap(MIN_GAP)`（2.8 m）と `setTau(1.0)` を設定される。`edf`・`none` ではさらに `setLaneChangeMode(0)`（SUMO の自律車線変更を止める）と `setSpeedMode(0)`（SUMO の安全速度と加減速の制約を止める）を設定する。以後，車線変更は `Layer2.execute_pairs` と `Discretionary.execute` の `changeLane` だけで，速度は `setSpeed` だけで動く。`setSpeed` は毎 step，`V2CAV.apply_speed_command` が 1 台に高々 1 回だけ出す（候補が無ければ出さない）。例外は障害物になる車で，`Obstacle.place`（`V2CAV.brake_as_obstacle`）・`V2CAV.make_obstacle`・停止を固定したあとの `control_speed` が直接 `setSpeed` する（02・05）。

## 調停ポリシー（`Policy`）

| 値 | Phase A | Phase B | 縦方向制御・`Layer2`・任意の車線変更 |
|---|---|---|---|
| `edf`（既定） | `EDF.order_requests` | `RSU.arbitrate` | 行う |
| `none` | `FCFS.order_requests`（活性化の早い順。同時なら ID の小さい順） | `RSU.arbitrate_fcfs`（目標車線で最も近い後続をそのまま提供車にする。障害物は提供車にせず，加速の途中の合流車には割り当てない。03） | 行う。`Layer2` は FCFS の順で要求を処理する |
| `off` | 行わない | 行わない | 行わない。車線変更と速度は SUMO（LC2013・Krauss）に任せる |
| `off-late` | 行わない | 行わない | `off` と同じ。ただし生成時に操作を持つ車は，いずれかの操作が活性化するまで `setLaneChangeMode(0)` で車線変更を止め，活性化した step に `SUMO_DEFAULT_LC_MODE`（`0b011001010101` = 1621）へ戻す（`V2CAV.update_activation`） |

- `off`・`off-late`（`Policy.is_noncooperative`）の車は `V2CAV(sumo_default_control=True)` で生成し，`setLaneChangeMode(0)`・`setSpeedMode(0)` を設定しない。
- 観測・活性化・締切達成の記録・TTC・現実性の検査・障害物の配置と回避操作の付与・衝突の検出は，全ポリシーで同じに動く。
- 障害物になる車は，`off`・`off-late` でも `V2CAV.start_obstacle_stop` で車線変更を止め，`V2CAV.make_obstacle` で `setSpeedMode(0)` にしてから止める。

## 環境（`Environment`）

`Environment`（frozen）は 1 つの評価環境の固定の構造を持つ。負荷（Q・f）は実行時に与える。

| フィールド | 意味 |
|---|---|
| `mainlane_edge` | 本線 edge（調停の区間） |
| `mainlane_length` | 区間長。各グループの締切 `deadline_pos` もこの値 |
| `groups` | 車のグループ（`Group`：`route`・`weight`・`target_lane`・`deadline_pos`・`depart_edge`・`depart_lanes`）。`target_lane` が `None` のグループは必須 LC を持たない（through） |
| `through_lanes` | 本線 edge のうち終端で本線へ続くレーン。障害物の回避先の選択と，回避後に戻る操作の目標に使う（02） |
| `request_at_entry` | `True` なら区間に入った時点から要求を出す（`default_activation_margin` が `mainlane_length` を返す）。`False` なら締切の `ACTIVATION_MARGIN`（400 m）手前から |
| `ramp_lanes` | 本線 edge のうち合流ランプから続く車線。ここから移る要求車は `MERGE_SPEED` まで加速してから移る（`LCRequest.accelerating_to_merge`。02） |

| 環境 | `mainlane_edge` | 車線数 | 区間長 = 締切 [m] | `through_lanes` | `request_at_entry` | `ramp_lanes` | 必須 LC のグループ（投入 edge → 目標レーン） |
|---|---|---|---|---|---|---|---|
| `diverge` | `DivergeZone` | 3 | 1000 | 0, 1, 2 | False | — | `exiting`（`DivergeZone` → 0） |
| `merge` | `MergeZone` | 3 | 240 | 1, 2 | True | 0 | `merging`（`OnRamp` → 1） |
| `straight` | `Road` | 3 | 1000 | 0, 1, 2 | False | — | なし（障害物を置くと回避操作が付く） |
| `weave` | `WeaveZone` | 3 | 275 | 1, 2 | True | 0 | `merging`（`OnRamp` → 1），`diverging`（`MainApproach` → 0） |
| `weave2` | `WeaveZone` | 4 | 610 | 1, 2 | True | 0, 3 | `merging_bottom`（`OnRampBottom` → 1），`merging_top`（`OnRampTop` → 2），`diverging_bottom`（`MainApproach` → 0），`diverging_top`（`MainApproach` → 3），`crossing_bt`（`OnRampBottom` → 3），`crossing_tb`（`OnRampTop` → 0） |

- どの環境にも through のグループ `through` が 1 つある（投入 edge は diverge・straight が本線 edge，ほかは `MainApproach`）。グループの `weight` はすべて 1.0，`depart_lanes` はすべて未指定（投入 edge の全レーン）。
- 道路網（`<env>.net.xml`）は `config/v2/build_networks.py` が環境ごとに nod・edg・con を書き，netconvert で作る（各環境の `build.sh` から呼ぶ）。区間の edge は `length` で長さを指定し，道路網の区間長が `mainlane_length` とちょうど一致するようにしてある。共通の値は `Geometry` にある（車線幅 3.5 m，本線 27.78 m/s，合流ランプ 11.11 m/s，出口ランプ 27.78 m/s，区間の手前の本線 500 m，合流ランプ 300 m，区間の後ろ 200 m）。

## 実行の準備（`V2Simulation._set_environment` と `run` の冒頭）

1. 区間長の照合：本線 edge の lane 0 の長さを traci で取り，`Environment.check_measured_length` で `mainlane_length` と比べる。0.01 m を超えて違えば `ValueError` で止める（道路網と環境の定義の片方だけを直した状態で走らせない）。測った長さと要求を出し始める位置（`V2Simulation.margin()`）を表示する。
2. `Environment.group_rates` で Q・f をグループ別の流入量に展開する。必須 LC のグループに f，through のグループに 1 − f を割り，同じ種類のグループの間は `weight` で分ける。必須 LC のグループが無い環境（straight）では f を無視して全車を through にする。
3. グループごとに k = int(rate × T / 3600) 台を流す。[0, T) の整数秒から k 個を `random.sample` で重複なく選び，0.1 s を足した時刻を流入時刻にする。グループの定義順に乱数を使うので，定義順を変えると同じ seed でも結果が変わる。
4. 障害物を指定したときは，`Obstacle.validate_for` でレーン番号（0 ≤ L < 本線 edge の車線数）と位置（0 < P < 区間長）を確かめ，範囲外なら `ValueError` で止める。`ObstacleMetrics` を用意する。
5. `SpeedLog.from_env()`：環境変数 `V2_SPEED_LOG` が設定されていれば速度ログを開く（06）。

## 毎 step の処理順（`V2Simulation.run`）

```
1. traci.simulationStep() → 衝突の検出（_check_collision）
2. t ≥ T になった最初の step で流入を締め切り，挿入待ちの車を remove する（_remove_pending_insertions）
3. 全車を順に見る
   - 到着した車: 流入の締切で remove した未発進の車なら何もしない。それ以外は統計に加え
                 （accumulate_exit_stats），失敗個票・要求個票・障害物の計測に足す（06）
   - 未発進の車: canceled に入れる
   - 走行中の車: その step に発進した車は発進時刻を記録 → 観測（update_self_observation）
                 → 活性化（update_activation）→ 締切達成の記録（update_deadline_achievement）→ TTC
4. 現実性の検査（Feasibility.count_violations・LaneChangeReversals.update。観測のみ）
5. 障害物: appear_time 以降は配置を進め（Obstacle.place），停車し終えたあとは毎 step 回避操作を付与する
   （Obstacle.escalate）→ ObstacleMetrics.step
6. Tc ごとの調停（edf・none だけ。TC = TIME_STEP = 0.1 s なので既定では毎 step）
   Snapshot.capture → LCRequest.build_all → Phase A（EDF.order_requests／FCFS.order_requests）
   → Phase B（RSU.arbitrate／RSU.arbitrate_fcfs）→ RSU.apply_roles（取りまとめ・Phase A・Phase B の時間を ArbitrationTiming.record で残す。06）
7. 走行中の全車の control_speed（追従の速度候補。05）（edf・none だけ）
8. Layer2.execute_pairs（必須の車線変更と，入れないときの速度候補。04）
   → Discretionary.execute（任意の車線変更。04）（最初の調停のあと，edf・none だけ）
9. 走行中の全車の apply_speed_command（候補から次 step の速度を 1 つ決めて setSpeed。05）
   → 採用した規則の数え上げ・速度ログ（edf・none だけ）
10. 到着した車をリストから削除し，流入時刻の車を投入する（_add_vehicle）
```

- 速度は候補として積む。7 の追従と 8 の `Layer2`（対向の 2 台の順番・提供車の譲り・スロット整列・締切前の保持）がそれぞれ `V2CAV.propose` で「規則名・目標速度・許す減速度／加速度」を足し，9 で次 step の速度が最も遅い候補を採って 1 回だけ `setSpeed` する（`SpeedArbiter.choose`。05）。呼ぶ順で指令が上書きされることはない。
- 車線変更は 8 で確定する。`Layer2.execute_pairs` はこの step に確定した車線変更を `committed`（目標レーン → (縦位置, 速度) のリスト）に積み，`Discretionary.execute` は同じ `committed` を見て，同じ step に同じ車線へ入る車との車間を確かめる（`Layer2._slot_free`）。任意の車線変更は要求車と未完了の操作を持つ車を対象にしないので，1 台が同じ step に 2 回 `changeLane` を受けることはない。
- 観測は 3 で全車分を先に済ませ，6 のスナップショットはその値を使う。ただし `Layer2` と `Discretionary` は判定の一部で traci にその場で問い合わせる（`getNeighbors`・`getSpeed`・`getBestLanes`・車線の制限速度など）。同じ step に出した `changeLane`・`setSpeed` が反映されるのは次の `simulationStep` なので，その場の問い合わせにも現れない。
- Tc を step より長くしたとき（`--set TC=...`）は，6 は Tc ごとにだけ走り，8 はその間の各 step で直近の Tc のスナップショット・割当・要求を使う。`Layer2.execute_pairs` は，調停のあとに本線 edge を出た車やレーンが変わった車の要求を実行しない（要求の鮮度。04）。
- `off`・`off-late` では 6〜9 を行わない（スナップショットが作られないので 8 も走らない）。
- `RSU.log_assignments`（Phase A/B の結果の表示）は，整数秒が 50 の倍数になった最初の調停で 1 回呼ぶ。

## 現実性の検査（`Feasibility.count_violations`・`LaneChangeReversals`）

挙動は変えない。毎 step，本線 edge 上の車の（車線，縦位置〔前端〕）を前の step と比べて，次の 3 つを数える。合計は終了時に表示するだけで，CSV には書かない（06）。

- 重なり：前の step から車線が変わった車について，移った先の車線に縦位置の差が `VEH_LENGTH`（5.0 m）未満の別の車がいれば 1 と数える（車体が縦に重なる位置への車線変更）。
- すり抜け：同じ 2 車線の間で逆向きに移った 2 台が，前の step で縦位置の差 `VEH_LENGTH` 未満に並んでいれば 1 組と数える（横に重なった 2 台が互いの車線へ移った）。
- 往復：車線を移った車が，直前の車線変更で出た車線へ `LC_REVERSAL_WINDOW`（3.0 s）以内に戻れば 1 と数える（SUMO の車線変更は 1 step で終わるが，現実の車は横へ移るのに数秒かかる）。

対象は前後どちらの step でも本線 edge にいる車だけである（レーン番号は edge ごとの番号のため）。全ポリシーで動く。

## 流入（`V2Simulation._add_vehicle`）

流入時刻になったグループの車を `traci.vehicle.add` で入れる（`typeID="CAV"`，`departPos="base"`，`departSpeed="last"`。投入 edge はグループの `depart_edge`，無ければ本線 edge）。投入レーンは，グループの候補レーン（`depart_lanes`，無ければ投入 edge の全レーン）のうち待ち行列が空のレーン（無ければ最も短いレーン）から `random.choice` で選ぶ。待ち行列は投入した車を積み，走り出した step に外す（`_update_lane_queue`）。待ち行列はレーン番号ごとに持ち，edge を区別しない。必須 LC のグループの車には，操作（`LCOperation(target_lane, deadline_pos)`）を 1 つ持たせる。

## 終了の条件とドレーン（`V2Simulation._should_continue`）

| 時刻 | 動き |
|---|---|
| t < T | 続ける |
| T ≤ t < T + `DRAIN_MAX`（900 s） | 発進済みで障害物でない車に未完了の操作（必須 LC・回避・回避後に戻る操作）が残っている間だけ続ける（`_has_pending_operations`） |
| t ≥ T + `DRAIN_MAX` | 終える |

流入を T で締め切ったあと，ネット上に残った操作が片付くまで掃き出してから終える。流入の締切では，その時点で走行中でも到着済みでもない車（SUMO の挿入待ち）を `traci.vehicle.remove` で取り除く。これらの車は canceled に数えたまま残り，走行時間・平均速度・締切達成には入らない。

## 終了時の処理

- 障害物を指定したのに最後まで配置できなかった場合は `RuntimeError` を投げる。
- 走行中のまま残った車は，平均速度を統計に入れ，緊急制動の回数を足し，締切達成を記録し（未完了として数えられる），失敗個票・要求個票に加える。
- 個票と追加の CSV を書き，結果を表示し，結果の CSV に 1 行を足して（06），traci を閉じる。

## SUMO 側の設定

- `--time-to-teleport -1`：詰まりによるテレポートを無効にする。
- 衝突したときの処理は sumocfg で指定しておらず，SUMO の既定（`collision.action=teleport`）で動く。衝突した車は `_check_collision` で `collided_ids` に入る。
- sumocfg の step の長さは 0.1 s（`TIME_STEP` と同じ），終了時刻は 6000 s。実際の終了は `_should_continue` が決める。
- 車種 `CAV`（各環境の rou）：`accel` 2.6，`decel` 5.0，`minGap` 2.8，`maxSpeed` 27，`length` 5，`speedFactor` 1.0，`speedDev` 0。
