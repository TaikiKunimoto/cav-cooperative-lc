# 01 全体構成とメインループ

## モジュール

| モジュール | クラス | 役割 |
|---|---|---|
| `__main__.py` | — | 引数（seed, Q, f, `--env`, `--obstacle`, `--nogui`）を読み，`random.seed(seed)` を呼び，SUMO を起動して `V2Simulation.run` を呼ぶ |
| `simulation.py` | `V2Simulation` | 1 回の実行の状態，毎 step のループ，流入，到着処理，統計への受け渡し |
| `v2_cav.py` | `V2CAV` | 1 台の状態・観測・縦方向制御，操作の活性化と完了の記録 |
| `lc_request.py` | `LCOperation`, `LCRequest` | 操作（目標レーン・締切）と，スナップショットから作る要求 |
| `snapshot.py` | `Snapshot`, `VehObs` | 調停のために凍結した全車の観測と，本線の車線別・縦位置降順の並び（`lane_members`） |
| `layer1/priority.py` | `EDF` | 実効距離と鍵，鍵順の並べ替え（Phase A） |
| `layer1/rsu.py` | `RSU`, `Assignment` | 提供車の割当（Phase B）と役割の付与 |
| `layer2/pair_executor.py` | `Layer2` | 車線変更の実行と，すぐに入れないときの速度調整 |
| `layer2/safety.py` | `Safety` | 安全ギャップ `G_req` と，次の 1 段の目標レーン |
| `obstacle.py` | `Obstacle` | 突発障害物の配置と，後続車への回避操作の付与 |
| `environment.py` | `Environment`, `Group` | 5 環境の形状と，Q・f からグループ別の流入量への展開 |
| `constants.py` | — | 物理定数と機構のパラメータ |

車は生成時（`V2CAV.model_post_init`）に `setLaneChangeMode(0)`（SUMO の自律車線変更を止める），`setSpeedMode(0)`（SUMO の安全速度の制約を止める），`setMinGap(2.8)`，`setTau(1.0)` を設定される。以後，車線変更は `Layer2` の `changeLane` だけで，速度は `slowDown`・`setSpeed` だけで動く。

## 実行の準備（`V2Simulation._set_environment`）

1. 本線 edge の lane 0 の実測長を取り，締切が公称長と等しいグループの `deadline_pos` を実測長に置き換える（`Environment.with_measured_length`）。
2. `Environment.group_rates` で Q・f をグループ別の流入量に展開する。必須 LC のグループに f，through のグループに 1 − f を割り，同じ種類のグループの間は `weight` で分ける。必須 LC のグループが無い環境（straight）では f を無視して全車を through にする。
3. グループごとに k = rate × T / 3600 台を流す。[0, T) の整数秒から k 個を `random.sample` で重複なく選び，0.1 s を足した時刻を流入時刻にする（T = 600 s）。グループの定義順に乱数を使うので，定義順を変えると同じ seed でも結果が変わる。

## 毎 step の処理順（`V2Simulation.run`）

```
1. traci.simulationStep() → 衝突の検出（_check_collision）
2. t ≥ T になった最初の step で流入を締め切り，挿入待ちの車を remove する（ドレーンの開始）
3. 全車を順に見る
   - 到着した車: 統計に加え（accumulate_exit_stats），失敗個票・要求個票に足して，リストから外す
   - 未発進の車: canceled に入れる
   - 走行中の車: 観測（update_self_observation）→ 活性化（update_activation）
                 → 締切達成の記録（update_deadline_achievement）
4. 障害物: appear_time 以降は配置を試み（Obstacle.place），配置後は毎 step 回避操作を付与する（Obstacle.escalate）
5. Tc ごとの調停（Tc = TIME_STEP = 0.1 s なので毎 step）
   Snapshot.capture → LCRequest.build_all → EDF.order_requests（Phase A）
   → RSU.arbitrate（Phase B）→ RSU.apply_roles
6. 走行中の全車の control_speed（縦方向制御，05）
7. Layer2.execute_pairs（車線変更と速度調整，04）
8. 到着した車をリストから削除し，流入時刻の車を投入する（_add_vehicle）
```

- 同じ車に同じ step で複数の速度指令が出たときは，後に出したものが効く。6 の `control_speed` の指令は，7 の `Layer2`（提供車の譲歩・締切前の hold・スロット整列）で上書きされうる。`Layer2` を最後に呼ぶのはそのため。
- 観測は 3 で全車分を先に済ませ，5 のスナップショットはその値を使う。ただし `Layer2` は判定の一部で traci にその場で問い合わせる（`getNeighbors`・`getSpeed`）。

## 流入（`V2Simulation._add_vehicle`）

流入時刻になったグループの車を `traci.vehicle.add` で入れる（`departPos="base"`，`departSpeed="last"`）。投入レーンは，グループの候補レーンのうち待ち行列が空のレーン（無ければ最も短いレーン）から `random.choice` で選ぶ。必須 LC のグループの車には，操作を 1 つ持たせる。

## 終了の条件とドレーン（`V2Simulation._should_continue`）

| 時刻 | 動き |
|---|---|
| t < T | 続ける |
| T ≤ t < T + `DRAIN_MAX`（900 s） | 発進済みで障害物でない車に未完了の操作（必須 LC・回避）が残っている間だけ続ける |
| t ≥ T + `DRAIN_MAX` | 終える |

流入を T で締め切ったあと，ネット上に残った操作が片付くまで掃き出してから終える。

## 終了時の処理

- 障害物を指定したのに最後まで配置できなかった場合は `RuntimeError` を投げる。
- 走行中のまま残った車は，締切達成を記録し（未完了として数えられる），失敗個票・要求個票に加える。
- 統計の CSV を書き（06），traci を閉じる。

## SUMO 側の設定

- `--time-to-teleport -1`：詰まりによるテレポートを無効にする。
- 衝突したときの処理は sumocfg で指定しておらず，SUMO の既定（`collision.action=teleport`）で動く。衝突した車は `_check_collision` で `collided_ids` に入る。
- step の長さは 0.1 s。
