# 02 要求と優先度

## 操作（`LCOperation`）

車は操作のリスト `V2CAV.operations` を持つ。操作 1 つは `(target_lane, deadline_pos, is_avoidance)` と，活性化・完了の状態からなる。

- 流入時に，必須 LC のグループの車は操作を 1 つ持つ。through の車は空。
- 障害物の回避は，元の操作を残したまま回避操作を 1 つ足す（下の「障害物」）。
- 完了しているか（`is_done`）: 通常の操作は「今のレーン == `target_lane`」，回避操作は「`lane_pos ≥ deadline_pos`（障害物を通過した）」。**現在の状態で毎回判定する**ので，目標レーンに着いたあと離れると，通常の操作は再び未完了になる（回避で一時的に退避した車が元の目標へ戻るのはこの仕組み）。
- アクティブな操作（`V2CAV.active_operation`）: 未完了の操作のうち `deadline_pos` が最小のもの。スナップショットと要求はこれを基準にする。

締切達成の記録（`completed_in_time`）は `is_done` とは別に持ち，一度立てたら戻らない（06）。

## 活性化（早め・固定）

`LCRequest.in_activation_window` は次をすべて満たすとき真になる。

- 本線 edge の上にいる
- 目標レーンにまだ着いていない
- `lane_pos ≥ deadline_pos − ACTIVATION_MARGIN`（400 m）

`V2CAV.update_activation` は，操作ごとに初めて窓に入った step で `activated = True` とし，`activation_time`・`activation_pos` を記録する（一度だけ）。締切が 400 m より手前にある環境（merge・weave・weave2）では，本線 edge に入った時点で窓の中にいる。

## 要求（`LCRequest`）

スナップショットの各車について `LCRequest.from_obs` が要求を作る。障害物の車と，窓の外の車は要求を出さない。

| 項目 | 値 |
|---|---|
| `direction` | `target_lane > lane` なら `CHANGE_LEFT`（番号が増える向き），それ以外は `CHANGE_RIGHT` |
| `remaining_k` | `|target_lane − lane|` |
| `wait_time` | `sim_time − activation_time` |

1 回の車線変更は 1 段だけ（`Safety.next_lane` = 今のレーン ± 1）。多段の車線変更は，段ごとに要求を作り直して進める。

## 実効距離と鍵（`EDF`）

```
dist = (D − pos) − (k − 1)·R        （R = 50 m）
key  = (dist, −wait_time, −current_pos, int(veh_id))   ← 昇順に並べる。小さいほど緊急
```

`veh_id` は一意なので，鍵に同点は出ない。鍵と dist は次に使う。

- Phase B で要求を処理する順番と，提供車の候補が「鍵が自分より劣位か」の判定（03）
- `Layer2` で要求を処理する順番（04）
- 締切前の hold に入るかの判定 `dist ≤ HOLD_MARGIN`（04）。多段の車は，実際の残り距離より早く hold に入る

## 障害物（`Obstacle`）

- 指定: `--obstacle lane,pos,time`。`validate_for` でレーン番号と位置の範囲を確かめ，範囲外なら `ValueError`。
- 配置（`place`）: `appear_time` 以降，指定レーンで `pos` より手前にいる先頭の車を 1 台監視し，その車が `lane_pos ≥ pos` になった step で障害物にする（`make_obstacle`：`setSpeed(0)`，`is_obstacle = True`）。監視していた車がレーンを外れたら選び直す。
- 回避操作の付与（`escalate`，毎 step）: 障害物より後ろで同じレーンにいる車に，回避操作（`target_lane` = 隣のレーン，`deadline_pos` = 障害物の位置，`is_avoidance = True`）を 1 つ足す。付与済みの車は飛ばす。
- 回避先（`_avoid_lane`）: 最終目的（回避でない操作のうち締切が最も遠いものの目標レーン）が左なら左，右なら右を優先し，行けなければ逆側。through の車と，最終目的が障害物のレーンの車は，両側に行けるなら `veh_id` の偶奇（偶数は右）で決め，片側だけならそちら。
- 障害物になった車の操作は消さない（活性化していれば母数に残り，未完了として数えられる）。障害物の車は要求を出さず（`from_obs`），提供車にも選ばれない（`RSU._find_provider`）。
