# 02 要求と優先度

## 操作（`LCOperation`）

車は操作のリスト `V2CAV.operations` を持つ。操作 1 つは `(target_lane, deadline_pos, is_avoidance, is_return)` と，活性化・完了の状態からなる。

- 流入時（`V2Simulation._add_vehicle`）に，目標レーンと締切を持つグループ（`Environment.groups`）の車は操作を 1 つ持つ。through の車は空。どの環境でも，グループの締切は本線 edge の終端（`deadline_pos` = `mainlane_length`）にある。
- 障害物の回避は，元の操作を残したまま回避操作（`is_avoidance`）を 1 つ足す。through の車には，回避のあとで本線へ戻る操作（`is_return`）も足すことがある（下の「障害物」）。
- 完了しているか（`is_done`）: 回避操作は「`lane_pos ≥ deadline_pos`（障害物を通過した）」，それ以外（通常の操作と戻る操作）は「今のレーン == `target_lane`」。**現在の状態で毎回判定する**ので，目標レーンに着いたあと離れると，通常の操作は再び未完了になる（回避で一時的に退避した車が元の目標へ戻るのはこの仕組み）。操作がすべて完了した車は任意の車線変更（04）の対象になるので，それで目標レーンを離れたときも，その操作は未完了に戻る。
- アクティブな操作（`V2CAV.active_operation`）: 未完了の操作のうち `deadline_pos` が最小のもの。スナップショット（`VehObs` の `target_lane`・`deadline_pos`・`activation_time`）と要求はこれを基準にする。

締切達成の記録（`completed_in_time`・`completion_time`・`completion_pos`）は `is_done` とは別に持ち，一度立てたら戻らない。戻る操作は締切達成の集計に入れない（06）。

## 活性化

`LCRequest.in_activation_window` は次をすべて満たすとき真になる。

- 本線 edge の上にいる
- 目標レーンにまだ着いていない
- `lane_pos ≥ deadline_pos − margin`

margin は `V2Simulation.margin()` が決める。`--activation-margin` を指定すればその値（正の値に限る），指定しなければ `Environment.default_activation_margin()` の値で，`request_at_entry` の環境（merge・weave・weave2）は区間長 `mainlane_length`，それ以外（diverge・straight）は `ACTIVATION_MARGIN`（400 m）。締切はどれも区間長以下なので，margin が区間長なら本線 edge に入った時点で窓の中にいる。

`V2CAV.update_activation` は毎 step，ポリシーによらず，操作ごとに初めて窓に入った step で `activated = True` とし，`activation_time`・`activation_pos` を記録する（一度だけ）。アクティブでない操作も判定する。`--policy off-late` では，操作が初めて活性化した step に，止めていた SUMO の車線変更を `SUMO_DEFAULT_LC_MODE` で解禁する（01）。

## 要求（`LCRequest`）

毎 Tc，スナップショットから `LCRequest.build_all(snap, margin, ramp_lanes)` が要求を作る（各車について `LCRequest.from_obs`）。障害物の車（`is_obstacle`。停車に向けて減速している間も含む）と，窓の外の車と，アクティブな操作の無い車は要求を出さない。

| 項目 | 値 |
|---|---|
| `direction` | `target_lane > lane` なら `CHANGE_LEFT`（番号が増える向き），それ以外は `CHANGE_RIGHT` |
| `current_lane`・`current_pos` | 今のレーンと縦位置 |
| `target_lane`・`deadline_pos` | アクティブな操作の目標レーンと締切 D |
| `remaining_k` | `|target_lane − lane|` |
| `wait_time` | `sim_time − activation_time`（活性化がまだ記録されていなければ 0） |
| `accelerating` | 合流の加速の途中か（下の「合流の加速」）。既定は偽 |
| `stage_deadline`（プロパティ） | 次の 1 段の締切（中間の締切）`D − (k − 1)·R` |

1 回の車線変更は 1 段だけ（`Safety.next_lane` = 今のレーン ± 1）。多段の車線変更は，段ごとに要求を作り直して進める。`Layer2` は要求を実行する前に，要求車がまだ本線 edge の `current_lane` にいるかを確かめ，いなければその要求を実行しない（04）。

## 合流の加速（`LCRequest.accelerating_to_merge`）

`Environment.ramp_lanes` は，本線 edge のうち合流ランプから続く車線（merge と weave は `(0,)`，weave2 は `(0, 3)`，diverge と straight は無し）。`build_all` は，`current_lane` がこの車線にあり，`accelerating_to_merge` が真になる要求に `accelerating` を立てる。

```
v_m = min(MERGE_SPEED, 次の 1 段の目標レーンで，縦位置が要求車以上の車のうち最も後ろの車の速度)
      （MERGE_SPEED = 65 km/h。そういう車がいなければ MERGE_SPEED）
加速の途中 ⇔ v < v_m  かつ  dist ≥ (v_m² − v²) / (2·MAX_ACCEL) + v_m² / (2·HOLD_DECEL)
```

v は要求車の速度，dist は下の実効距離（`MAX_ACCEL` = 2.6 m/s²，`HOLD_DECEL` = 2.5 m/s²）。今の速度が v_m に届いたら，または残りの距離が足りなくなったら（v_m まで加速すると締切の手前で `HOLD_DECEL` で止まれない位置），`accelerating` は立たず，ふつうの要求として今の速度のまま挿入の判定を受ける。

`accelerating` の要求は次のように扱われる。

- RSU は提供車を割り当てない（03）。鍵は計算され，ほかの要求車の提供車選びの鍵の比較に使われる。この車自身がほかの要求車の提供車に選ばれることはある。
- `Layer2` は車線変更させず，対向の 2 台の順番にも加えない。整列と締切前の保持は続ける（04）。

加速のための専用の速度指令は無い。制限速度と追従の候補で加速する（05）。

## 実効距離と鍵（`EDF`）

```
dist = (D − pos) − (k − 1)·R        （R = 50 m）
key  = (dist, −wait_time, −current_pos, int(veh_id))   ← 昇順に並べる。小さいほど緊急
```

`EDF.order_requests` が，同じスナップショットから作った全要求の鍵を計算して昇順に並べる（Phase A）。`veh_id` は一意なので，鍵に同点は出ない。鍵と dist は次に使う。

- Phase B で要求を処理する順番と，提供車の候補が「鍵が自分より劣位か」の判定（03）
- `Layer2` で要求を処理する順番（04）。挿入を試す順番なので，同じ step に同じ目標レーンへ入る車どうしでは鍵の上位が先に確定する。対向の 2 台の順番では，鍵の劣位の車が上位の車の後ろへ下がる
- 挿入できなかった要求車が締切前の保持に入るかの判定 `_hold_pos − pos ≤ HOLD_MARGIN`（155 m）。`STAGE_HOLD`（既定 1.0）が正なら保持の位置 `_hold_pos` は `stage_deadline` なので，判定は `dist ≤ HOLD_MARGIN` と同じになり，速度の上限も中間の締切で止まれる速度になる。`STAGE_HOLD = 0` なら保持の位置は D（04）
- 合流の加速の判定（上）

`--policy none` では，鍵を `FCFS.make_key` の `(−wait_time, 0, 0, int(veh_id))` に替える（`FCFS.order_requests`）。活性化の早い順で，dist は使わない。Phase B（`RSU.arbitrate_fcfs`，03）と `Layer2` の処理順も，この鍵の順になる。

## 障害物（`Obstacle`）

- 指定: `--obstacle lane,pos,time`（`Obstacle.from_spec`。形式が違えば `ValueError`）。`validate_for` で `0 ≤ lane < レーン数` と `0 < pos < mainlane_length` を確かめ，範囲外なら `ValueError`。
- 配置（`place`）: `appear_time` 以降，配置が終わるまで毎 step 呼ぶ。
  1. 本線 edge の指定レーンで，まだ `OBSTACLE_DECEL`（2.5 m/s²）の減速で `pos` の手前に止まれる車（`lane_pos + v²/(2·OBSTACLE_DECEL) < pos`）のうち，最も前の 1 台を監視する（毎 step 選び直す）。
  2. 監視している車が `lane_pos + v²/(2·OBSTACLE_DECEL) ≥ pos` になった step に，`start_obstacle_stop(pos)` で障害物にする（`is_obstacle = True`，停止位置 `obstacle_stop_pos = pos`，車線変更を止める）。以後，`obstacle_brake_decel`（`pos` で止まる減速度を `OBSTACLE_DECEL` 以上 `|MAX_DECEL|` 以下に収めた値。`pos` を越えていれば `|MAX_DECEL|`）で減速させる。提案の車では `control_speed` の候補（規則 `stopping`）として入る（05）。
  3. 速度が 0 になった step に `make_obstacle`（速度モード・車線変更モードを 0，`setSpeed(0)`，`obstacle_stop_pos = None`）で停止を固定し，配置を終える。そのときの `lane_pos` を障害物の位置とする。
  - 最後まで配置できなければ，終了時に `RuntimeError` を出す（`V2Simulation.run`）。
- 回避操作の付与（`escalate`，配置後は毎 step）: 本線 edge の障害物のレーンで障害物より後ろ（`lane_pos < 障害物の位置`）にいる車に，回避操作（`target_lane` = `_avoid_lane` が選ぶ隣のレーン，`deadline_pos` = 障害物の位置，`is_avoidance = True`）を 1 つ足す。through の車も必須 LC の車も対象。付与済みの車と，隣のレーンが無い車は飛ばす。
- 回避先（`_avoid_lane`）: 最終目的（回避でも戻るでもない操作のうち締切が最も遠いものの目標レーン）が左なら左，右なら右を優先し，行けなければ逆側。through の車と，最終目的が障害物のレーンの車は，存在する隣のレーンを候補にし，その中に `Environment.through_lanes`（本線 edge のうち終端で本線へ続くレーン）があればそれに絞る。候補が 2 つなら `veh_id` の偶奇（偶数は右），1 つならそれ。
- 戻る操作: 目標を持たない車（回避・戻る以外の操作が無い車）が `through_lanes` に入っていないレーンへ回避するときは，戻る操作（`target_lane` = 回避先に最も近い `through_lanes` のレーン〔同じ距離なら番号の小さい方〕，`deadline_pos` = `mainlane_length`，`is_return = True`）も足す（1 台に 1 つまで）。回避操作の方が締切が近いので，障害物を通過するまでは回避操作がアクティブで，通過すると戻る操作がアクティブになる。
- 回避先のレーンに着いた車は，障害物を通過するまで回避操作がアクティブのままだが，目標レーンにいるので要求を出さない。通過すると回避操作が完了し，元の操作（あれば）や戻る操作がアクティブになる。
- 障害物になった車の操作は消さない（活性化していれば母数に残り，未完了として数えられる。06）。障害物の車は要求を出さず（`from_obs`），提供車にも選ばれない（`RSU._find_provider`・`RSU.arbitrate_fcfs`）。停車に向けて減速している間も `is_obstacle` は真なので，同じ扱いになる。
