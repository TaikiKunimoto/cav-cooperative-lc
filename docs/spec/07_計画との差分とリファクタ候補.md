# 07 計画との差分・リファクタ候補・要確認の点

## 確定版計画との差分

`../実装計画_EDF統一調停_確定版.md`（設計時の仕様）と現行のコードが違うところ。

| 計画 | 現行のコード |
|---|---|
| §4.1 挿入に要るギャップ = `MIN_GAP × 0.5 + g_req × Δv / MAX_SPEED` | 相対制動 ＋ 追跡遅れ ＋ 余裕（`Safety.net_required`）。`getNeighbors` の距離は minGap 控除済みとして扱い，目標レーンの先のジャンクション内・次の edge の先行車も見る（04） |
| §4.2 提供車は `_supporting_speed`（要求車の速度の 0〜30%）まで減速 | `_provider_yield`：後続側の隙間が足りないとき（`YIELD_ON_FRONT=2` では，前側の不足を提供車の後ろの余裕で賄えるときも）だけ，「要求車の速度 − `YIELD_DELTA`」（要求車の速度の `YIELD_MIN_RATIO` 以上）へ `YIELD_DECEL` 以下で減速する。`YIELD_MAX_DURATION` で交代し，`YIELD_COOLDOWN` のあいだ選ばれない。止まった要求車には `_yield_to_stopped`（03・04） |
| §4.3 要求車は目標レーンの先行の速度まで自己減速（`_requester_match_target_speed`） | `_requester_align_to_slot`：前側が足りなければ，足りない先行車のうち最も遅い車より `ALIGN_DELTA` 遅く（`ALIGN_DECEL` 以下），後続側だけが足りなければ `ALIGN_DELTA` 速く（04） |
| 記載なし | 対向の 2 台の順番（`_order_opposite_pairs`・`_stay_behind`）。鍵の低い方が高い方の後ろへ下がる。PR #72 で対向スワップ（横に重なった 2 台が同じ step に互いのレーンへ移る）を削除して置き換えた（04） |
| 記載なし | 中間の締切での保持（`STAGE_HOLD`。2 回以上移る要求車は D − (k − 1)·R で保持）と，同じ step の挿入どうしの車間（`_slot_free`）（04） |
| 記載なし | 合流ランプから続くレーンの要求車は `MERGE_SPEED` まで加速してから移る（`LCRequest.accelerating`。02） |
| 記載なし | 任意の車線変更（`Discretionary`。速度利得で，提供車を付けずに隣へ移る）（04） |
| §5 縦方向制御 | 要素ごとに速度の候補を出し，`SpeedArbiter` が最も遅い候補を毎 step 1 回だけ `setSpeed` する。追従は相対制動と時間車頭 `FOLLOW_TAU`，臨界制動バンドと緊急制動が加わった（05） |
| §7 挿入と追従が同じ `G_req` を使う | 挿入・同じ step の車間・対向の 2 台・譲りは `Safety.net_required`，追従は `max(net_required, v·FOLLOW_TAU) + MIN_GAP`（下の定義一覧）。`Safety.g_req` はどこからも呼ばれていない |
| §10 メトリクス | ドレーン方式，実測の締切，回避操作の別集計，衝突の別掲，個票 CSV，車線変更の現実性の検査，任意の車線変更の集計が加わった（01・06） |
| §12 保証 | コードで対応するのは検証用の数え上げ（`RSU.keys_unique`・`RSU.providers_unique`）だけ |

`constants.py` の冒頭のコメントは，確定版ではなく旧計画（`実装計画_EDF統一調停.md` §7）を指している。

## 距離・ギャップの定義一覧

安全の判定はほぼ `Safety.net_required(v後, v前) = max(0, (v後² − v前²) / (2·|MAX_DECEL|)) + v後·LC_REACTION_LAG + LC_SAFETY_MARGIN` に集まった。比べる距離は，SUMO の `getLeader`・`getNeighbors`・`getFollower` が返す minGap 控除済みの距離（バンパー間 − minGap）か，縦位置（前端）から同じ基準に直した値。

| 使う場所 | 何と比べるか | 閾値 | 距離の基準 |
|---|---|---|---|
| `control_speed` の緊急制動 | 1 step 後の `leader_distance`（`gap − Δv·Δt`） | 前車速度へ揃える減速 Δv²/(2·room) が `\|MAX_DECEL\|` を超える | minGap 控除済み |
| `control_speed` の臨界制動バンド | `leader_distance` | `(v² − v前²)/(2·\|MAX_DECEL\|) + 1.0 + 0.2·v` | 同上 |
| `control_speed` の追従 | `leader_distance` | `max(net_required(v, v前), v·FOLLOW_TAU) + MIN_GAP`（要確認 1） | 同上 |
| `_closing_decel` の同速の車間 | 同上 | `max(net_required(v前, v前), v前·FOLLOW_TAU) + MIN_GAP` | 同上 |
| 挿入判定（`_insertion_check_live`），任意の車線変更の条件 2 | `getNeighbors` の距離（先行側は `_front_neighbors` でジャンクションの先も） | 後続側 `net_required(v後続, v自)`，先行側 `net_required(v自, v先行)` | minGap 控除済み |
| 同じ step の挿入どうし（`_slot_free`） | 前端の縦位置の差 − `VEH_LENGTH` − `MIN_GAP` | `net_required` | 控除済みに直して比べる |
| 対向の 2 台の順番（`_stay_behind`） | 同上 | 前側 `net_required(v高, v低)`，後ろ側 `net_required(v低, v高) + LC_SAFETY_MARGIN` | 同上 |
| 提供車の譲り（`_provider_yield`） | 同上 | `net_required(v提供, v要求)` ＋ 前側の不足量（前側の譲りのとき） | 同上 |
| 前側の譲りの余裕（`_front_room_from_rear_slack`） | `getFollower` の距離 | 追従と同じ `max(net_required, v·FOLLOW_TAU) + MIN_GAP` を超える分 | minGap 控除済み |
| 要求車の整列（`_requester_align_to_slot`） | `_front_neighbors` の距離 | `net_required(v自, v先行)` | 同上 |
| 止まった要求車の手前で止まる位置（`Safety.stop_pos_behind`） | 要求車の前端の縦位置 | `VEH_LENGTH + MIN_GAP + 2·LC_SAFETY_MARGIN` 手前 | 前端 |

## リファクタ候補

1. **残っている別系統の式を 1 か所（`Safety`）に集める。** 臨界制動バンド（1.0 m・0.2 s）と緊急制動の式は `control_speed` に直書きしている。追従の安全車間 `max(net_required, v·FOLLOW_TAU) + MIN_GAP` は，`control_speed` と `_front_room_from_rear_slack` に同じ式が別々に書かれている。
2. **「次の 1 段の目標レーン」の計算が重複している。** `Safety.next_lane`，`LCRequest`（`lc_request.py`），`RSU` の 2 か所（`step = 1 if … CHANGE_LEFT else -1`）。
3. **`V2Simulation.run` が長い（約 250 行）。** 到着処理・障害物・調停・制御・終了処理をメソッドに分ける。
4. **名前の無い数値がある。** 臨界制動バンドの 1.0 m・0.2 s（`control_speed`）。名前付きの定数にする。
5. **使われていないもの。** `Safety.g_req`，`MAX_SPEED`（v2 では参照なし。車線の制限速度は SUMO から取る），`LCOperation.wait_time()`（`LCRequest.from_obs` が同じ計算をしている），`V2CAV` の `pos_x`・`pos_y`・`providing_to_id`・`receiving_from_id`（書き込むだけで読まれない。後の 2 つは `RSU.apply_roles` が書く）。
6. **古いコメント。**
   - `constants.py` の `MAX_ACCEL` のコメントは，もう無い `_safe_accel_duration`・`slowDown` に触れている。
   - `traci_wrapper.get_veh_neighbors` の docstring は距離を「minGap 込みの実ギャップ」と書いているが，`Layer2` は minGap 控除済みとして扱っている（PR #56 で直した扱いが正しい）。
   - `Layer2.execute_pairs` の docstring は，名前の変わる前の `_insertion_safe_live` を指している。`_insertion_check_live` の docstring の式には，追跡遅れと余裕の項が無い。`_provider_yield` の docstring は「後続側の不足のときだけ呼ばれる」と書いているが，`YIELD_ON_FRONT=2` では前側の不足でも呼ばれる。`pair_executor.py` の冒頭の保持の説明は「締切 D までの実距離」のまま（コードは `_hold_pos`）。
   - `control_speed` の docstring は，車間が不足して前車より遅いときの減速を「`FOLLOW_MIN_DECEL` 以下」と書いているが，コードは少なくとも `FOLLOW_MIN_DECEL` で減速する。
   - `V2CAV.update_deadline_achievement` の docstring は「車線変更は Layer2 でしか起きない」と書いているが，任意の車線変更でも起きる。`lc_request.py` と `V2CAV.update_activation` の docstring は活性化の窓を「既定で `ACTIVATION_MARGIN`」と書いているが，merge・weave・weave2 は区間長（02）。`obstacle.py` の冒頭と `simulation.py` のコメントは回避の付与先を「through 車」と書いているが，`Obstacle.escalate` は障害物でない後続すべてに付ける。
7. **SUMO_HOME を `sys.path` に足す定型文が 5 モジュールにある。**
8. **`simulation.py` に TODO が残っている。** 「ここ本当に必要か，一回で良いのか？」（`update_activation` の呼び出し）。
9. **浮動小数を等値で比べている。** `_add_vehicle` の `sumo_time not in depart_times`，`_should_continue` の `sumo_time % 10 == 0`。
10. **リストでの所属判定（`vid in arrived_list`）が，車の数に比例して重い。** set にする。

## 要確認の点（挙動にかかわるかもしれない）

1. **追従の安全車間は minGap を 2 回数えている。** `leader_distance`（`getLeader`）は minGap 控除済み（SUMO の API の説明「The distance is measured from the front + minGap to the back of the leader」。`control_speed` の docstring もそう書いている）。追従はこれを `max(net_required, v·FOLLOW_TAU) + MIN_GAP` と比べるので，目標の車間はバンパー間で `max(net_required, v·FOLLOW_TAU) + 2·MIN_GAP` になる（同速なら 27 m/s で約 32.6 m，停止で 6.1 m）。挿入判定・`_slot_free`・譲りは控除済みの距離を `net_required` と比べる（バンパー間で `net_required + MIN_GAP`）。SUMO の Krauss（`setTau(1.0)`・minGap 2.8 m）は，控除済みの距離に対して安全速度を決める。`_front_room_from_rear_slack` も追従と同じ式で後ろの余裕を測る。
2. **`Tc > TIME_STEP` にすると，`Layer2` は Tc ごとの要求を毎 step 使う。** 実行前に要求車が本線上で同じレーンにいるかは確かめる（04）が，同じ step の確定（`committed`）や保持の残り距離には要求の縦位置 `req.current_pos` を使うので，その値は Tc ごとにしか更新されない。今は `TC = TIME_STEP` なので起きない。
3. **衝突したときの処理が sumocfg にも起動の引数にも書かれていない。** SUMO の既定（`collision.action` は teleport）に頼っている。`__main__.py` が渡すのは `--time-to-teleport -1`（詰まりのテレポートを無効）だけ。
4. **速度の候補が無い step は指令を出さない。** `control_speed` は `lane_id` が取れないと候補を出さず，`apply_speed_command` は指令を出さないので，その step は前の `setSpeed` の値が残る。
5. **緊急制動の回数は，`emergency` の候補を出した回数。** 採用されたかは見ていない（05・06）。
