# 07 計画との差分・リファクタ候補・要確認の点

## 確定版計画との差分

`../実装計画_EDF統一調停_確定版.md`（設計時の仕様）と現行のコードが違うところ。

| 計画 | 現行のコード |
|---|---|
| §4.1 挿入に要るギャップ = `MIN_GAP × 0.5 + g_req × Δv / MAX_SPEED` | 相対制動 ＋ 追跡遅れ ＋ 余裕（`_net_required`）。`getNeighbors` の距離は minGap 控除済みとして扱う（04） |
| §4.2 提供車は `_supporting_speed`（要求車の速度の 0〜30%）まで減速 | `_provider_yield` の 4 通り：追い越し／courtesy hold，不足に比例した減速，詰め，同じ速度（04） |
| §4.3 要求車は目標レーンの先行の速度まで自己減速（`_requester_match_target_speed`） | `_requester_align_to_slot`：前に対向要求車がいれば −`ALIGN_DELTA`，後ろにいれば +`ALIGN_DELTA`，それ以外は従来どおり（04） |
| 記載なし | 対向スワップ（`_execute_swaps`）と，RSU がスワップの相手を提供車に選ばない規則（03・04） |
| §5 縦方向制御 | 臨界制動バンドが加わった（05） |
| §7 挿入と追従が同じ `G_req` を使う | 追従は `G_req`，挿入とスワップは `_net_required`，提供車は独自の `required`（下の定義一覧） |
| §10 メトリクス | ドレーン方式，実測の締切，回避操作の別集計，衝突の別掲，個票 CSV が加わった（01・06） |
| §12 保証 | コードで対応するのは検証用の数え上げ（`keys_unique`・`providers_unique`）だけ |

`constants.py` の冒頭のコメントは，確定版ではなく旧計画（`実装計画_EDF統一調停.md` §7）を指している。

## 距離・ギャップの定義一覧

同じ「前の車との間隔」を，場所ごとに別の式・別の基準で測っている。

| 使う場所 | 何と比べるか | 閾値 | 距離の基準 |
|---|---|---|---|
| `control_speed` の緊急減速 | `leader_distance`（`getLeader`） | `MIN_GAP` | minGap 控除済み（要確認 1） |
| `control_speed` の臨界制動バンド | `leader_distance` | `(v² − v_f²)/(2 × 5) + 1.0 + 0.2 v` | 同上 |
| `control_speed` の追従 | `leader_distance` | `safety_gap` = `G_req(v)`（`MIN_GAP` を含む） | 同上 |
| hold・整列・提供車の加速可否 | `leader_distance` | `safety_gap`（提供車の加速は ＋車長） | 同上 |
| 挿入・スワップの実測検査 | `getNeighbors` の `dist` | `_net_required` | minGap 控除済みとして扱う |
| スワップのスナップショット検査 | 前端の位置 − 車長 | `_net_required` | バンパー間（minGap を引いていない） |
| 提供車の譲歩 | 前端どうしの距離 | `VEH_LENGTH + 1.5 × MIN_GAP + G_req × Δv / MAX_SPEED` | 前端間 |
| 同じ step のスロット・スワップの窓 | 縦位置の差 | `VEH_LENGTH + MIN_GAP` | 前端間 |

## リファクタ候補

1. **距離・ギャップの定義を 1 か所（`Safety`）に集める。** 上の一覧のとおり，今は 5 系統の式がある。距離の基準（前端間・バンパー間・minGap 控除済み）も揃っていない。
2. **「次の 1 段の目標レーン」と左右の計算が重複している。** `Safety.next_lane`，`RSU._find_provider`，`RSU._is_swap_partner`，`Layer2` の `going_right`／`lat` ビット（3 か所）。
3. **`_insertion_safe_live` と `_swap_live_gap_ok` がほぼ同じ。** 違いは，相手の除外と壁ペアの緩和だけ。
4. **`V2Simulation.run` が長い（約 170 行）。** 到着処理・障害物・調停・制御・終了処理をメソッドに分ける。
5. **名前の無い数値がある。** `_provider_yield`（1.5, 0.7, 2, 5.0, 3.0, 2.0, 1.0），`control_speed`（1.0 m, 0.2 s, −1 m/s），あちこちの 0.1 m/s。名前付きの定数にする。
6. **使われていないもの。** `LCOperation.wait_time()`（`LCRequest.from_obs` が同じ計算をしている），`V2CAV` の `emergency_brake_counter`・`pos_x`・`pos_y`・`length`・`providing_to_id`・`receiving_from_id`（書き込むだけで読まれない）。
7. **SUMO_HOME を `sys.path` に足す定型文が 4 モジュールにある。**
8. **`simulation.py` に TODO が残っている。** 「ここ本当に必要か，一回で良いのか？」（`update_activation` の呼び出し）。
9. **浮動小数を等値で比べている。** `_add_vehicle` の `sumo_time in depart_times`，`_should_continue` の `sumo_time % 10 == 0`，`RSU._find_provider` の `speed != 0`。
10. **リストでの所属判定（`vid in arrived_list` など）が，車の数に比例して重い。** set にする。

## 要確認の点（挙動にかかわるかもしれない）

1. **`getLeader` の距離は minGap 控除済み。** SUMO の API の説明に「The distance is measured from the front + minGap to the back of the leader, so it does not include the minGap of the vehicle」とある。`control_speed`・hold・整列・提供車は，この値を `MIN_GAP` や `safety_gap`（`MIN_GAP` を含む）と比べているので，実際の閾値はバンパー間で `MIN_GAP`（2.8 m）ぶん大きくなっている。PR #56 で `getNeighbors` について直した二重取りと同じ形。TTC の統計も同じ距離を使っている。
2. **`getLeader(id, 0)` の探索距離。** 0 は「制動距離から先読みの距離を決める」という意味。遠くの先行車は見えず（`None`），「先行車なし」として制限速度へ加速する分岐に入る。
3. **`setSpeed` と `slowDown` が混ざっている。** 緊急減速と障害物は `setSpeed`（`-1` で解除するまで続く），ほかは `slowDown` を使う。`setSpeed` の後に `slowDown` を出したとき，`slowDown` の期間が終わってからどちらが効くかは SUMO の実装次第で，コードでは `setSpeed(-1)` による解除をしていない。
4. **指令を出さない分岐がある。** `control_speed` の 7・9，hold と整列の早期 return では，前の step までの `slowDown` が続く。そのとき実際にどの速度になるかは，直前の指令の残り時間しだいになる。
5. **`Tc > TIME_STEP` にすると，`Layer2` が古い要求で動く。** 要求（位置・レーン）は Tc ごとにしか作り直さないが，`Layer2` は毎 step 実行する。今は `Tc = TIME_STEP` なので起きない。
6. **衝突したときの処理が sumocfg に書かれていない。** SUMO の既定（テレポート）に頼っている。
7. **hold に入る判定と hold の減速で，距離が違う。** 判定は実効距離（多段の車は R ぶん前倒し）で行い，減速は実際の残り距離（D − pos）で計算している。
