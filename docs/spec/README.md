# v2 の仕様（現行コードの記述）

`TraCI/v2/`（提案手法：統一調停）が**いま実際に何をしているか**を，コードから読み起こしてまとめたもの。
設計時の仕様は `../実装計画_EDF統一調停_確定版.md` にあるが，その後の修正（PR #48・#49・#56・#66・#70・#72・#73・#74・#75 など）で実装が変わっている。計画との食い違いは `07_計画との差分とリファクタ候補.md` にまとめた。

- 基準のコード: main の `57326e2`（2026-10-20）。コードを変えたら，該当するファイルも直す。
- 書くのはコードの振る舞いだけ。評価結果とその解釈は書かない。
- 場所は行番号ではなく，クラス名・メソッド名で指す。

| ファイル | 中身 |
|---|---|
| `01_全体構成とメインループ.md` | 実行の引数，モジュール構成，調停ポリシー，評価環境，毎 step の処理順，現実性の検査，流入・ドレーン・終了処理 |
| `02_要求と優先度.md` | 必須 LC の操作・活性化・要求・合流の加速・EDF の鍵・障害物の回避と戻りの操作 |
| `03_上位層_提供車の割当.md` | RSU の Phase B（割当・占有印・譲歩の伝播・止まった要求車への選び方）と役割の付与 |
| `04_下位層_車線変更の実行.md` | 挿入の判定・同じ step のスロット・対向の 2 台の順番・提供車の譲り・スロット整列・締切前の保持・任意の車線変更 |
| `05_縦方向制御.md` | `control_speed`（追従・臨界制動バンド・緊急制動）と速度の調停（`SpeedArbiter`），速度ログ |

## 用語

| 用語 | 意味 |
|---|---|
| 操作（`LCOperation`） | 車が済ませるべき車線変更 1 つ。目標レーン `target_lane` と締切位置 `deadline_pos`（D） |
| 要求車 | 活性化窓の中にいて，アクティブな操作が未完了の車 |
| 提供車 | 要求車のために後ろで減速してすき間を開ける役に割り当てられた車 |
| 本線 edge | 環境ごとの調停区間（`Environment.mainlane_edge`）。縦位置 `lane_pos` はこの edge の始端から測る |
| 実効距離 dist | `(D − pos) − (k − 1)·R`。k は残りの車線変更の段数 |
| レーン番号 | 0 が右端（最下段）。`CarAction.CHANGE_LEFT` は番号が増える向き |

## 挙動が変わっていないかの確かめ方

v2 のリファクタでは，`uv run python tests/golden/run_golden.py check --suite v2` が差分ゼロになることを確かめる（`tests/golden/README.md`）。
