# 05 縦方向制御と速度の調停（`V2CAV.control_speed`・`SpeedArbiter`）

速度は，追従（`control_speed`）と下位層（`Layer2`）がそれぞれ**候補**として積み，`V2CAV.apply_speed_command` が 1 つに決めて，1 台につき 1 step に 1 回だけ `setSpeed` を出す（PR #66）。車は `setSpeedMode(0)` なので SUMO の安全速度や加減速の上限は効かない。`SpeedArbiter` と `apply_speed_command` のクリップが，速度にかかる唯一の上限になる。`slowDown` は使わない。

## 毎 step の流れ

```
1. update_self_observation   先行車とその速度・加速度を取り，速度候補を空にする
2. control_speed             追従の候補を積む（この文書）
3. Layer2.execute_pairs      車線変更と，入れない要求にかかわる候補（order・yield・hold・align）を積む（04）
   Discretionary.execute     任意の車線変更。速度の候補は出さない
4. apply_speed_command       候補から次 step の速度を 1 つ決め，setSpeed を 1 回だけ出す
```

2 と 4 は走行中の全車（本線 edge の外を含む）に行う。非協調のポリシー（`--policy off`・`off-late`）では 2〜4 を行わず，SUMO の標準の制御に任せる（01）。

候補（`SpeedCandidate`）は「規則名 `rule`，目標速度 `target`，そこへ向かうときに許す減速度 `decel`，許す加速度 `accel`」の組。`accel` の既定値は `MAX_ACCEL`（2.6 m/s²）で，今はどの規則も `accel` を指定しない。目標速度が非負の有限値でない，減速度が正の有限値でない，加速度が非負の有限値でないときは `ValueError` を投げる。

## 先行車（`update_self_observation`）

- `leader = getLeader(id, LEADER_LOOKAHEAD)`。`LEADER_LOOKAHEAD`（200 m）は探索距離の下限（`getLeader` の第 2 引数。0 だと自車の制動距離から決まる）。探索距離の中であれば，ジャンクションの先（次の edge）にいる車も先行車になる。
- `leader_distance` は `getLeader` が返す距離。自車の前端 ＋ minGap から先行車の後端までで，バンパー間から minGap を差し引いた値になる。以下の「車間 gap」はすべてこの値。
- `leader_speed` は先行車の `getSpeed`，`leader_accel` は先行車の `getAcceleration`（直近 step の加速度。減速中は負）。
- 先行車がいなければ 3 つとも `None`。
- `leader_distance`・`leader_speed` は TTC の統計にも使う（06）。

## 追従の候補（`control_speed`）

上から順に処理する。「終わる」と書いたところで，それ以降の候補は出さない。

```
if 障害物:
    停車し終えている（obstacle_stop_pos が None） → setSpeed(0) を直接出して終わる（候補は出さない）
    停車中                                     → stopping を積む（続けて下も行う）
if 走行レーン lane_id が分からない → 終わる
limit を積む
if 先行車がいない → 終わる
if Δv > 0:
    緊急制動の条件を満たす → emergency を積んで終わる
    臨界制動バンドに入っている → critical を積んで終わる
follow を積む
```

Δv = v − v_先行（v は自車の速度）。

| 規則 | 積む条件 | 目標速度 | 許す減速度 |
|---|---|---|---|
| `stopping` | 障害物として停車中 | 0 | `obstacle_brake_decel()`（下の「障害物」） |
| `limit` | 走行レーンが分かれば常に | 今のレーンの制限速度（`getMaxSpeed(lane_id)`） | `abs(MAX_DECEL)`（5.0 m/s²） |
| `emergency` | Δv > 0 で，`needed > abs(MAX_DECEL)` | v_先行 | `min(needed, EMERGENCY_DECEL)`（上限 9.0 m/s²） |
| `critical` | Δv > 0 で，緊急でなく `gap < braking_needed` | v_先行 | `abs(MAX_DECEL)` |
| `follow` | 先行車がいて，上の 2 つに当たらない | 下の「追従」 | 下の「追従」 |

### 緊急制動（`emergency`）

```
room   = gap − Δv × TIME_STEP              ← 両車が今の速度のまま 1 step 進んだあとの車間（TIME_STEP = 0.1 s）
needed = Δv² / (2 × room)                  ← room ≤ 0 なら無限大
```

needed は，前車の速度へ揃えるまでに車間が 0 を割らない（バンパー間が `MIN_GAP` を割らない）相対の減速度。前車の加減速は見込まない。needed が `abs(MAX_DECEL)` を超えたときだけ `emergency` を積み，`emergency_brake_counter` を 1 増やす（候補を積んだ回数で，採用されたかは問わない）。全車の合計は実行の最後に `Speed: emergency brake events` として出力する（06）。`abs(MAX_DECEL)` を超える減速を `SpeedArbiter` が許すのは，この規則名（`SpeedArbiter.EMERGENCY` = `"emergency"`）の候補だけ。

### 臨界制動バンド（`critical`）

```
braking_needed = (v² − v_先行²) / (2 × abs(MAX_DECEL)) + 1.0 + 0.2 × v
```

gap がこれを下回ったら，最大減速で前車の速度へ揃える候補を積む。1.0 m と 0.2 s は名前の無い数値。

### 追従（`follow`）

```
safety_gap = max(Safety.net_required(v, v_先行), v × FOLLOW_TAU) + MIN_GAP     （FOLLOW_TAU = 1.0 s，MIN_GAP = 2.8 m）
target     = max(0, min(制限速度, v_先行 + FOLLOW_GAIN × (gap − safety_gap)))   （FOLLOW_GAIN = 0.5 1/s）
lead_brake = max(0, −leader_accel)                                              ← 前車の今の減速度（加速中・一定なら 0）
below      = gap < safety_gap
```

目標は，車間が safety_gap ちょうどのとき前車の速度になり，余剰に比例して前車より速く，不足に比例して遅くなる。

| 場合 | 目標速度 | 許す減速度 |
|---|---|---|
| Δv > 0 | below なら `min(target, v_先行)`，そうでなければ `target` | `_closing_decel(v, v_先行, gap, below, lead_brake)` |
| Δv ≤ 0 で below でない | `target` | `abs(MAX_DECEL)` |
| Δv ≤ 0 で below | `target` | `min(max(FOLLOW_MIN_DECEL, _keep_safety_decel(v, v_先行, lead_brake)), abs(MAX_DECEL))`（`FOLLOW_MIN_DECEL` = 1.0 m/s²） |

Δv ≤ 0 で below でないときは，制限速度が自車の速度より低くない限り目標は今の速度以上になり，加速の大きさは候補の `accel` と，調停の加速度の上限（下の「速度の調停」）で決まる。

`_closing_decel`（前車より速いときの減速度。前車が今の減速を続けると見込む）:

```
s_eq   = max(Safety.net_required(v_先行, v_先行), v_先行 × FOLLOW_TAU) + MIN_GAP   ← 前車の速度で同速になったときの安全車間
room   = max(gap − s_eq, (gap − MIN_GAP) / 2)
needed = Δv² / (2 × room) + lead_brake                                         ← room ≤ 0 なら abs(MAX_DECEL) + lead_brake
below なら needed = max(needed, _keep_safety_decel(v, v_先行, lead_brake))
結果を FOLLOW_MIN_DECEL 〜 abs(MAX_DECEL) に収める
```

基本は「車間 − s_eq の距離で同速になる相対の減速度」に前車の減速度を足したもの。gap が `2 × s_eq − MIN_GAP` より小さいと `(gap − MIN_GAP) / 2` の方が大きくなり，`Δv² / (gap − MIN_GAP)` を使う。

`_keep_safety_decel`（車間が `Safety.net_required(v, v_先行)` より速く縮まない減速度）:

```
v ≤ 0 なら 0
b = (Δv + v_先行 × lead_brake / abs(MAX_DECEL)) / (v / abs(MAX_DECEL) + LC_REACTION_LAG)     （LC_REACTION_LAG = 0.25 s）
```

車間は Δv で縮み，net_required は自車の減速 b で `(v / abs(MAX_DECEL) + LC_REACTION_LAG) × b`，前車の減速で `(v_先行 / abs(MAX_DECEL)) × lead_brake` だけ変わる，という関係から出した値。`FOLLOW_TAU` の項と `MIN_GAP` は入らない。Δv ≤ 0 で前車が減速していなければ 0 以下になり，そのときは `FOLLOW_MIN_DECEL` が使われる。

### 障害物（`stopping` と停止の固定）

- `Obstacle.place` が `start_obstacle_stop(stop_pos)` を呼ぶと，`is_obstacle = True`，`obstacle_stop_pos` = 指定位置になり，`setLaneChangeMode(0)` を出す（障害物の配置は 02）。
- 停車中は `stopping` を積む。減速度は `obstacle_brake_decel()` = `min(abs(MAX_DECEL), max(OBSTACLE_DECEL, v² / (2 × 残り距離)))`（`OBSTACLE_DECEL` = 2.5 m/s²。残り距離 = `obstacle_stop_pos − lane_pos` が 0 以下なら `abs(MAX_DECEL)`）。続けて `limit`・`follow` などの追従の候補も積むので，前が詰まっていれば遅い方が採られる。
- `Obstacle.place` は停車中の車に毎 step `brake_as_obstacle`（`v − obstacle_brake_decel() × TIME_STEP` を `setSpeed`）も出す。非協調でないポリシー（`edf`・`none`）の車では，同じ step のあとで `apply_speed_command` が `setSpeed` を出すので，そちらが効く。
- 止まったら（速度 0 以下）`Obstacle.place` が `make_obstacle` を呼び，`obstacle_stop_pos = None`，`setSpeedMode(0)`・`setLaneChangeMode(0)`・`setSpeed(0)` を出す。以後 `control_speed` は `setSpeed(0)` を直接出して候補を積まず，`apply_speed_command` は候補を捨てて `"obstacle"` を返す。

## 下位層が積む候補

| 規則 | 積むメソッド | 役割 |
|---|---|---|
| `order` | `Layer2._stay_behind` | 対向の 2 台のうち，優先度の低い方が高い方の後ろへ下がる |
| `yield` | `Layer2._provider_yield`・`Layer2._yield_to_stopped` | 提供車の譲り |
| `hold` | `Layer2._hold_before_deadline` | 締切前の保持（保持の位置で止まれる速度を上限にする） |
| `align` | `Layer2._requester_align_to_slot` | 要求車のスロット整列 |

条件・目標速度・減速度は 04。`Discretionary`（任意の車線変更）は速度の候補を出さない。候補は追従の候補のあとに積まれる。

## 速度の調停（`SpeedArbiter.choose`・`V2CAV.apply_speed_command`）

```
各候補 c の次 step の速度（Δt = TIME_STEP）:
  next(c) = max(0, min(max(c.target, v − c.decel × Δt), v + c.accel × Δt))
採用    = next(c) が最小の候補。同点なら先に積まれた候補
v_next  = next(採用)
v_next  = max(v_next, v − cap × Δt)        cap = EMERGENCY_DECEL（採用が emergency のとき）／ abs(MAX_DECEL)（それ以外）
v_next  = min(v_next, v + MAX_ACCEL × Δt)
v_next  = max(0, v_next)                   ← ここまで SpeedArbiter.choose
v_next  = min(v_next, v + a_cap × Δt)      a_cap = min(MAX_ACCEL, max(a_prev, 0) + ACCEL_JERK × Δt)
setSpeed(id, v_next)
```

- 積む順は `stopping` → `limit` → `emergency`／`critical`／`follow` → 下位層の候補。`emergency` 以外の規則が許す減速度は，定数の既定の値ではどれも `abs(MAX_DECEL)` 以下なので，候補を足すと次 step の速度は下がるか変わらないかのどちらかになり，下位層の候補が追従の候補より速い指令になることはない。
- **加速度の上限（ジャーク）**：a_prev は前 step の加速度（`speed_history` の最後の 2 つの差 ÷ Δt。記録が 1 つしか無ければ 0）。加速度は，a_prev（減速中なら 0）から 1 step に `ACCEL_JERK × Δt`（`ACCEL_JERK` = 2.5 m/s³）までしか上げない。減速の側は制限しない。
- `speed_rule`・`speed_target`・`speed_next` に，採用候補の規則名・目標速度と指令した速度を入れる。クリップやジャークの制限で次速度が変わっても，規則名は採用候補のものを入れる。
- 候補が 1 つも無いとき（走行レーンが分からず障害物でもないとき）は `setSpeed` を出さず，`speed_rule = None` にして `"none"` を返す。停車し終えた障害物は `"obstacle"` を返す。
- 返した規則名を `V2Simulation` が車・step ごとに数え，実行の最後に `Speed: rule counts (vehicle-steps)` として出力する（06）。
- 役割（`status` の `YIELDING`・`LANE_CHANGING`）は速度の判定に使わない。

## 縦方向制御で使う距離の定義

比べる相手はどれも gap（`leader_distance`，minGap を差し引いた距離）。

| 名前 | 式 | 使う場所 |
|---|---|---|
| `Safety.net_required(v_back, v_front)` | `max(0, (v_back² − v_front²) / (2 × abs(MAX_DECEL))) + v_back × LC_REACTION_LAG + LC_SAFETY_MARGIN`（`LC_SAFETY_MARGIN` = 0.5 m） | safety_gap・s_eq・`_keep_safety_decel` の導出。挿入判定など 04 と同じ定義 |
| safety_gap | `max(net_required(v, v_先行), v × FOLLOW_TAU) + MIN_GAP` | `follow`。同じ式を `Layer2._front_room_from_rear_slack` が提供車の後続の余裕に使う（04） |
| s_eq | `max(net_required(v_先行, v_先行), v_先行 × FOLLOW_TAU) + MIN_GAP` | `_closing_decel` |
| braking_needed | `(v² − v_先行²) / (2 × abs(MAX_DECEL)) + 1.0 + 0.2 × v` | `critical` |
| needed（緊急） | `Δv² / (2 × (gap − Δv × TIME_STEP))` | `emergency`（`abs(MAX_DECEL)` を超えたら発動） |

- gap が minGap を差し引いた距離なので，バンパー間でいえばどの閾値も `MIN_GAP` ぶん大きい。safety_gap と s_eq は式の中にも `MIN_GAP` を含むので，バンパー間では `MIN_GAP` を 2 回分含む。
- `Safety.g_req`（空走 ＋ 制動距離 ＋ `MIN_GAP` の安全ギャップ）は残っているが，v2 のどこからも呼ばれない。

## 速度ログ（`V2_SPEED_LOG`）

環境変数 `V2_SPEED_LOG=<path>` を与えたときだけ，`SpeedLog` が毎 step，`apply_speed_command` のあとに走行中の全車について 1 行ずつ CSV に書く（非協調のポリシーでは書かない）。

| 列 | 中身 |
|---|---|
| `time` | シミュレーション時刻（小数 1 桁） |
| `veh` | 車 ID |
| `road` | edge ID |
| `lane` | 車線番号（edge ごとに数える） |
| `lane_pos` | edge の始端からの縦位置（小数 2 桁） |
| `speed` | この step に観測した速度 |
| `next_speed` | 指令した次 step の速度（`speed_next`） |
| `rule` | 採用した規則名（`speed_rule`） |
| `target` | 採用候補の目標速度（`speed_target`） |
| `status` | 役割（`CarStatus` の名前：`NORMAL`・`YIELDING`・`LANE_CHANGING`） |
| `yield_for` | 提供車がいま譲っている要求車の ID（PR #67）。提供車でなくなると空に戻る |

`"none"`・`"obstacle"` を返した step は `speed_rule` などを書き換えない（`"none"` では `speed_rule` だけ `None` にする）ので，その行の `target`・`next_speed`（停車し終えた障害物では `rule` も）は，最後に候補を採用した step の値のまま。
