# 03 上位層：提供車の割当（`RSU`）

毎 Tc，Phase A で鍵順に並べた要求を，緊急な順に処理する（`RSU.arbitrate`）。`RSU` はスナップショットだけを読み，traci は読まない。`TC` は `TIME_STEP`（0.1 s）なので，既定では毎 step 割当を作り直す（`TC` を step より長くすると，割当と要求は次の Tc まで使い回される。01・04）。協調しないポリシー（`--policy off`・`off-late`）では呼ばれない。

```
if COOP_YIELD ≤ 0: 割当なし                ← 下の「協調減速を外す」
claimed = {}                               ← 今回すでに提供車として確保された車
for (key, req) in 鍵の昇順:
    if req.veh_id in claimed: continue     ← 自分が上位の車の提供車になっている（譲歩の伝播）
    if req.accelerating: continue          ← 合流の加速の途中（02）。まだ提供車を割り当てない
    provider = _find_provider(req, key)
    if provider: claimed に入れ，割当 (req ← provider) を加える
```

割当が無くても，要求車は条件が合えば自力で車線変更できる（04）。割当は「提供車が後ろで減速して，すき間を開ける」ためのもの。割り当てられた提供車が実際に減速するのは，要求車の自力の挿入が後続側の隙間不足で落ちたとき（`YIELD_ON_FRONT` によっては前側の不足のときも）だけ（`Layer2._provider_yield`，04）。

## 譲歩の伝播

上位の要求車の提供車として確保された要求車には，その Tc は自分の提供車を割り当てない。自分の車線変更は止めない。`Layer2` は鍵順に挿入を試すので，隙間があれば自力で入る（04）。その step に自力で車線を移ったときは，`Layer2` はその車に上位の要求車のための譲りを出さない（目標レーンから出ていくため。PR #74）。

## 提供車の候補（`RSU._find_provider`）

候補は，次の 1 段の目標レーン（今のレーン ± 1）にいる本線 edge 上の車（`Snapshot.lane_members`，縦位置の降順）。本線 edge の外（手前の edge やジャンクションの内部レーン）の車は候補にならない。次の条件をすべて満たす車を，近い順に残す。

1. 要求車より後ろ（`lane_pos < req.current_pos`。縦位置は前端）
2. 障害物でない（`is_obstacle`。停車に向けて減速している車も除く）
3. 譲りの交代の直後でない（`yield_cooldown_until ≤ sim_time`）。走行中の同じ要求車に譲った時間（`yield_time`。隙間が足りずに減速の候補を出した step だけ数える）が `YIELD_MAX_DURATION`（5.0 s）に達した提供車には，`Layer2._provider_yield` が譲りをやめさせ，`yield_cooldown_until = 時刻 + YIELD_COOLDOWN`（5.0 s）を書く（04）
4. まだ確保されていない（`claimed` にない）
5. 要求を出していない，または鍵が要求車より劣位（相手の鍵 > 自分の鍵）

自分の今のレーンを目指す対向の要求車も，鍵が劣位なら候補に残る（`Layer2` の対向の 2 台の順番でも，その車は要求車の後ろへ下がる。04）。合流の加速の途中の要求車も，鍵が劣位なら候補に残る。

選び方は，スナップショットでの要求車の速度で分ける。

- `YIELD_MIN_SPEED`（1.0 m/s）以上: 最も近い候補。毎 Tc 選び直し，今の提供車を続ける規則は無い。
- `YIELD_MIN_SPEED` 未満（止まった要求車）: 入る場所の手前の停止位置 `stop_pos = Safety.stop_pos_behind(req.current_pos)` = `pos − VEH_LENGTH − MIN_GAP − 2·LC_SAFETY_MARGIN`（要求車の前端から 8.8 m 後ろ。提供車の前端をここで止める）を使い，次の順に選ぶ。
  1. 今この要求車に譲っている候補（`VehObs.yield_for == req.veh_id`）が，最大減速で `stop_pos` に止まれる（`speed ≤ Safety.stop_speed(stop_pos − lane_pos, |MAX_DECEL|)`）なら，その車を続けて選ぶ。上限の速度で近づく提供車は 1 step だけ `HOLD_DECEL` の曲線を上回って見えることがあり，そのたびに役を入れ替えないためのもの。
  2. そうでなければ，`HOLD_DECEL`（2.5 m/s²）で `stop_pos` に止まれる（`speed ≤ Safety.stop_speed(stop_pos − lane_pos)`）最も近い候補。それより近くて止まれない車は選ばない（そのまま通り過ぎる）。
  3. どちらも無ければ割当なし。

  `Safety.stop_speed(room, decel)` は `√(2·decel·room)`（`room ≤ 0` なら 0）なので，前端がすでに `stop_pos` より前にある候補は，止まっているときだけ条件を満たす。選ばれた提供車は，`stop_pos` で止まれる速度を上限にして走る（`Layer2._yield_to_stopped`，04）。

## 役割の付与（`RSU.apply_roles`）

毎 Tc，走行中の全車を `NORMAL`・対応なしに戻してから，割当の要求車を `LANE_CHANGING`（`receiving_from_id` = 提供車），提供車を `YIELDING`（`providing_to_id` = 要求車）にする。最後に，`YIELDING` でない車の `yield_for` を消し，`yield_time` を 0 に戻す（提供車でなくなったら譲りの継続時間を数え直す）。

- `Layer2` が譲りを出す相手は，`status` ではなく割当のリストで決める（04）。
- `status` は速度の規則を変えない（役割による加速の禁止は無い。05）。`status` を読むのは，任意の車線変更の条件（`YIELDING` の車はしない。04）と速度ログの `status` 列（`SpeedLog`）だけ。
- `providing_to_id`・`receiving_from_id` も書き込まれるが，どこからも読まれていない（07）。
- `yield_for`・`yield_time`・`yield_cooldown_until` は `Layer2` が書く（04）。`yield_for` と `yield_cooldown_until` は `Snapshot.capture` が `VehObs` に写し，`_find_provider` が読む。`yield_for` は速度ログにも出る。

## 協調減速を外す（`COOP_YIELD = 0`）

`COOP_YIELD`（既定 1.0）が 0 以下なら，`RSU.arbitrate` も `RSU.arbitrate_fcfs` も空の割当を返す。全車が `NORMAL` になり，提供車の譲りは起きない。自力の挿入・対向の 2 台の順番・整列・締切前の保持はそのまま動く（04）。`--set COOP_YIELD=0` で指定する。

## 優先度なし（`--policy none`，`RSU.arbitrate_fcfs`）

Phase A は発生順の鍵（`FCFS`，02）。Phase B の `RSU.arbitrate_fcfs` は，その順に各要求（合流の加速の途中のものは飛ばす）について，次の 1 段の目標レーンで要求車より後ろにいて障害物でない最も近い車を，提供車にする。`arbitrate` にあって，こちらに無いものは次のとおり。

- 鍵の劣位の判定（自分より緊急な要求車も提供車にする）
- 占有印（同じ車を複数の要求車の提供車にしてよい）
- 譲歩の伝播（提供車に選ばれた要求車にも提供車を割り当てる）
- 止まった要求車への選び方（常に最も近い車）
- 譲りの交代の直後の除外（`yield_cooldown_until` を見ない）

同じ車が要求車と提供車を兼ねることがあり，`apply_roles` では割当のリストで後に来た方の役割が残る。止まった要求車に割り当てられた車が，すでに `stop_pos` で止まれない速さなら，その車は譲らずに通り過ぎる（`Layer2._yield_to_stopped`，04）。

## 検証用の数え上げ

毎 Tc，`keys_unique`（鍵に同点がないか）と `providers_unique`（同じ提供車が二重に割り当てられていないか）を調べ，成り立たなかった Tc の回数を終了時に表示する。`arbitrate` では占有印があるので `providers_unique` は常に成り立つ。`arbitrate_fcfs` では成り立たないことがある。

シミュレーション時刻の整数部が 50 の倍数になった最初の Tc には，`RSU.log_assignments` が要求の数・割当の数と，要求ごとの鍵の第 1 要素（`dist=` と表示する。優先度なしでは `−wait_time`）・k・提供車を表示する。
