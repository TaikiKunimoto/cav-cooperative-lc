# 03 上位層：提供車の割当（`RSU`）

毎 Tc，Phase A で鍵順に並べた要求を，緊急な順に処理する（`RSU.arbitrate`）。

```
claimed = {}                           ← 今回すでに提供車として確保された車
for (key, req) in 鍵の昇順:
    if req.veh_id in claimed: continue ← 自分が上位の車の提供車になっている。今回は自分の車線変更を見送る（譲歩の伝播）
    provider = _find_provider(req)
    if provider: claimed に入れ，割当 (req ← provider) を加える
```

割当が無くても，要求車は条件が合えば自力で車線変更できる（04）。割当は「提供車が後ろで減速して，すき間を開ける」ためのもの。

## 提供車の候補（`RSU._find_provider`）

候補は，次の 1 段の目標レーン（今のレーン ± 1）の本線上の車（縦位置の降順）。次の条件をすべて満たす車を，近い順に残す。

1. 要求車より後ろ（`lane_pos < req.current_pos`）
2. 障害物でない
3. まだ確保されていない（`claimed` にない）
4. 要求を出していない，または鍵が要求車より劣位（相手の鍵 ≥ 自分の鍵）
5. 対向スワップの相手でない（`_is_swap_partner`：相手の次の目標が要求車の今のレーンで，縦位置の差が `SWAP_WINDOW` = 車長 + minGap = 7.8 m 以内）。このペアは提供車にせず，`Layer2` の対向スワップで解く（04）

要求車の速度が 0 でなければ最も近い候補を，ちょうど 0 なら 2 番目に近い候補を選ぶ（候補が 1 台だけなら割当なし）。

## 役割の付与（`RSU.apply_roles`）

毎 Tc，走行中の全車を `NORMAL`・対応なしに戻してから，割当の要求車を `LANE_CHANGING`，提供車を `YIELDING` にする。

- `status` が使われるのは，`control_speed` の「加速しない」判定（`do_not_speed_up`）だけ（05）。
- `providing_to_id`・`receiving_from_id` も書き込まれるが，どこからも読まれていない（07）。

## 検証用の数え上げ

毎 Tc，`keys_unique`（鍵に同点がないか）と `providers_unique`（同じ提供車が二重に割り当てられていないか）を調べ，成り立たなかった回数を終了時に表示する。
